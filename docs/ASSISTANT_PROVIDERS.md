# Провайдеры локального помощника

Контракт `IAssistantProvider` и `AssistantProviderRegistry` отделяют вызов модели от интерфейса. Неизвестный ID разрешается в отключённый провайдер, который не запускает процесс и ничего не загружает. В настройках Windows есть явное отключение ИИ; сканирование, отчёты и очистка продолжают работать. Linux пока работает полностью без ИИ.

По умолчанию используется закреплённая Qwen. Чтобы выбрать другую локальную GGUF-модель, создайте `model.json` в каталоге данных и перезапустите приложение. Поля соответствуют `ModelDescriptor`: `id`, `fileName` (только имя `.gguf`), `downloadUri` (HTTPS), `sizeBytes`, `sha256` (64 hex-символа), `license`, `licenseUri` (HTTPS). Размер и SHA-256 нужно брать у доверенного издателя конкретного файла; приложение не угадывает их.

На экране анализа можно запросить подсказку для выбранного файла, на экране программ — для возможных остатков. Модель получает размер, условный номер и подсказку о типе по известному расширению. Пути остаются в интерфейсе. Советы предлагают, что проверить вручную, поскольку по этим метаданным нельзя установить владельца файла или возможность безопасного удаления.

Загрузка начинается только после отдельного подтверждения с размером и лицензией. Worker перед каждым запуском проверяет размер и SHA-256 выбранного профиля. Неподдерживаемый GGUF или нехватка памяти завершаются ошибкой; 8 ГБ — минимальный порог интерфейса для штатной модели, не гарантия достаточной памяти для других моделей.

Профили Llama/Phi конкретных версий и их качество в этой среде не проверялись. Облачный OpenRouter-провайдер пока не реализован: запросы и сводки не передаются в облако.
