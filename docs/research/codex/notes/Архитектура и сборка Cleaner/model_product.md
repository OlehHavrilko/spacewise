# Локальная модель продукт и дизайн Cleaner

Дата проверки источников: 23 октября 2026. Основание требований — полностью прочитанный локальный PROJECT_PROMPT_RU.md. Ниже факты отделены от проектных предложений; измерения приложения, UX-исследования и модельные испытания не выполнялись. Не выдавать предложенные бюджеты за результаты тестирования.

## Какую модель и runtime выбрать

### Takeaway
Предлагаю llama.cpp в изолированном непривилегированном процессе, GGUF и CPU как обязательный базовый backend. Кандидат первого профиля — Qwen3.5-2B Q4_K_M; окончательный выбор после одинакового RU/UK/EN набора оценок против Qwen3-4B-Instruct-2507 и Phi-4-mini-instruct. Модель объясняет и ранжирует уже найденные факты; определения категорий и разрешения находятся вне неё.

### Cited Findings
- llama.cpp распространяется под MIT и поддерживает локальный inference с CPU, Vulkan, CUDA и другими backend; права на runtime не заменяют права на веса. — [репозиторий](https://github.com/ggml-org/llama.cpp), [LICENSE](https://github.com/ggml-org/llama.cpp/blob/master/LICENSE)
- Qwen3.5-2B — модель с визуальным encoder, карточка указывает Apache-2.0 и покрытие 201 языков/диалектов. Это заявление автора о семействе, а не доказательство качества объяснений файловой системы на русском. — [карточка Qwen](https://huggingface.co/Qwen/Qwen3.5-2B)
- Просмотренный community GGUF содержит Q4_K_M 1.27 GB, Q6_K 1.56 GB, Q8_0 2.01 GB; отдельно лежит визуальный projector 671 MB. Для текстового сценария Cleaner projector не нужен. Это размер опубликованных артефактов, не RSS и не VRAM. — [дерево файлов](https://huggingface.co/lmstudio-community/Qwen3.5-2B-GGUF/tree/main)
- Для Qwen3.5-2B-Q4_K_M.gguf опубликован SHA256 `0bfe35afc9f05b7fac3fa04925e051ac7939a42a8a17ea11afc99701bea826cc`. Перед выпуском нужно привязать его к неизменяемой ревизии и собственному подписанному manifest: ссылка main меняется. Ничего не скачивалось и собственная хеш-проверка не выполнялась. — [страница файла](https://huggingface.co/lmstudio-community/Qwen3.5-2B-GGUF/blob/main/Qwen3.5-2B-Q4_K_M.gguf)
- Qwen3.5-0.8B тоже имеет Apache-2.0; годится кандидатом облегчённого профиля, но меньший размер сам по себе не доказывает достаточное качество. — [карточка](https://huggingface.co/Qwen/Qwen3.5-0.8B)
- Qwen3-4B-Instruct-2507: 4.0B параметров, Apache-2.0, только non-thinking режим; не надо ожидать `<think>` и включать режим рассуждений. — [карточка](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)
- Phi-4-mini-instruct: MIT; среди поддержанных языков названы русский и украинский. Авторы отмечают возможность галлюцинаций имён функций и URL в function calling. Поэтому модельную tool-call строку нельзя исполнять. — [карточка Microsoft](https://huggingface.co/microsoft/Phi-4-mini-instruct)
- ONNX Runtime GenAI имеет MIT, API C#/C/C++/Python, Windows и управление generation/KV cache; матрица включает Phi и Qwen. Поддержка семейства не доказывает совместимость каждой версии и каждого Execution Provider с выбранным quantized artifact. — [официальный репозиторий](https://github.com/microsoft/onnxruntime-genai)
- Актуальная документация ONNX Runtime называет DirectML направлением sustained engineering и предпочитает Windows ML; для более старых Windows управление моделью и провайдерами остаётся задачей приложения. Это аргумент против решения «всем обязательно NPU/Windows ML» в MVP. — [Windows integration](https://onnxruntime.ai/docs/get-started/with-windows.html)
- Apache-2.0 при распространении требует копию лицензии, сохранение соответствующих notices и указание изменений; NOTICE обрабатывается, если имеется. MIT требует сохранения copyright/permission notice. Для GPU библиотек действуют собственные условия, например CUDA runtime. — [Apache 2.0](https://www.apache.org/licenses/LICENSE-2.0), [MIT llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/LICENSE), [Microsoft third-party notices](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/third-party-notices)

### Inferences
- Runtime decision table: llama.cpp — основной путь благодаря portable CPU/GGUF и одному формату; ONNX Runtime GenAI — альтернативный adapter при доказанном выигрыше на конкретных Windows/NPU конфигурациях; Windows ML/Foundry Local — исследовать позднее для современного hardware, не делать обязательной зависимостью; Ollama/LM Studio не требовать от пользователя как отдельную установленную программу и не считать лицензии их продукта лицензией на встраивание.
- В release manifest хранить model ID, upstream revision, converter commit, quantizer commit, GGUF schema/version, runtime commit, backend, tokenizer/chat-template hash, SHA256, bytes, license/notice links, min app version и evaluation suite version. Предпочтительно своя воспроизводимая конверсия официальных весов; community quant допустим после документированной проверки происхождения и качества.
- Жизненный цикл: NotInstalled → CheckingSpace → Downloading(.partial) → Paused → Verifying → Ready → Loading → Running → Unloaded. Боковые состояния: FailedDownload, InvalidHash, IncompatibleRuntime, OutOfMemory, Cancelled. Загрузка только по явному действию; остановка и продолжение, проверка места до загрузки, атомарная активация после hash, сохранение рабочей версии до проверки новой. При несовпадении hash файл не исполнять/не загружать. Один подписанный manifest, allowlist HTTPS origin, запрет arbitrary URL из ответа модели. Обновления модели отдельно от приложения, release notes и возможность отката.
- Начальные **оценочные бюджеты**, не минимумы производителя: текстовый 2B Q4 на CPU целиться в 2–3 GiB private working set процесса при контексте 4096 и коротком ответе, full-system минимум для испытаний 8 GiB RAM; качественный 4B профиль — 4–6 GiB process budget и 16 GiB system RAM; модель выключена — приложение должно работать на слабой машине. На CPU выделенная VRAM не нужна. GPU профиль принимать только после измерения peak VRAM; нельзя писать «1.27 GB файл значит нужна 1.27 GB VRAM». Реальный бюджет включает weights, KV/recurrent state, compute buffers, allocator и driver.
- Начальный контекст 4096 tokens, ответ до 512 tokens, один inference за раз, отмена, time budget, CPU threads не все логические ядра; разгрузка при бездействии и перед очисткой. Голос, изображения, полный длинный контекст и чтение документов не входят в задачу. Автоматически уменьшить контекст/перейти на CPU только с ясным сообщением, затем deterministic explanation fallback.
- Benchmark protocol: фиксировать CPU/RAM/GPU/driver/Windows/power mode/runtime/model hash; холодный и тёплый запуск, prompt 512/2048/4096, output 128/512, p50/p95 TTFT/total latency, tokens/s, peak private bytes/VRAM, размер загрузки и install peak, cancel latency, power draw/нагрев если измеритель доступен. Матрица: 8GB iGPU laptop, 16GB modern CPU, 32GB + discrete GPU. Пример целевых ворот для референсного 16GB CPU: объяснение до 15s p95 и отмена до 1s; это команда должна подтвердить или изменить по пилоту.

### Gaps
- Нет замеров на целевых ПК, русского Cleaner eval и head-to-head quantization. Нельзя утверждать превосходство Qwen3.5 над Phi либо гарантировать скорость.
- Не проверены конкретные native binding package, ABI и стабильный runtime commit: это deliverable implementation spike. Название семейства Qwen в ONNX matrix не сертификат совместимости 3.5.

## Как встроить интеллект без права удаления

### Takeaway
Модель — недоверенный генератор предложений. Даже полностью захваченная prompt injection модель не должна получить путь от текста к удалению, эскалации, shell или обходу исключений.

### Cited Findings
- llama.cpp преобразует **подмножество** JSON Schema в GBNF. Grammar помогает синтаксису, но полнота schema и семантика требуют прикладного валидатора. — [grammar docs](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md)
- OWASP рекомендует ограничивать полномочия и держать авторизацию за пределами LLM; prompt injection включает инструкции в недоверенных данных. Фильтры и системный prompt не дают абсолютной защиты. — [OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/), [prevention cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

### Inferences
- Пайплайн: Scanner → immutable ScanSnapshot → deterministic RuleEngine → Finding catalog → redacted ContextBuilder → ModelHost → ProposalSchemaValidator → PolicyValidator → отображение предложения. Только отдельный пользовательский выбор в PlanBuilder → independent ExecutionPolicy → подтверждение → executor. Нет model→executor вызова.
- Модель получает application/category ID, category description из подписанного каталога, size totals, counts, age buckets, evidence IDs, exclusion labels. По умолчанию нет absolute path, username, document text, credential/environment values. Папки становятся `item_123`; связь с настоящими путями остаётся в UI/application service. Имена файлов тоже недоверенные и могут содержать «игнорируй правила»; ограничивать длину, экранировать, не смешивать с инструкциями. Markdown output без HTML, активных ссылок, embedded images и запусков URI.
- При необходимости tools только `get_scan_summary(snapshotId)`, `list_findings(snapshotId, categoryId, cursor)`, `get_finding_evidence(findingId)`; typed аргументы, UUID/enum, hard bounds, read-only immutable snapshot, никакого `read_file(path)` или SQL/shell. Произвольные пути и сетевые tools отсутствуют.
- Минимальный результат модели: `{schemaVersion, snapshotId, status:ok|insufficient|unknown, summaries:[{findingId, evidenceIds, explanation, certainty:known|inferred|unknown}], proposedFindingIds:[], questions:[]}`. Модель не определяет bytes, risk, delete method, eligible и checkbox state; UI берёт их из engine. additionalProperties=false, длины/массивы ограничены; каждый ID должен принадлежать snapshot и допустимой области.
- Отказы: parse/unknown field/foreign ID/stale snapshot/omitted consequence/evidence mismatch/timeout/OOM → никаких изменений плана, короткое «Не удалось проверить предложение; доступны обычные результаты». Retry максимум один с корректной формой, затем fallback. Недостаточная цель: вернуть максимально доступный объём при текущих ограничениях, не расширять scope. При пользовательском «не трогай загрузки» вначале записать exclusion constraint, затем модель, а не пытаться извлечь обязательный запрет из красивого ответа.
- Журналировать только latency/status/model version/schema rejection code без prompt и путей по умолчанию. Локальная история требует ACL, ограниченного retention и удаления через настройки; выгрузка diagnostics отдельное opt-in с предварительным просмотром redaction. Даже model download/update раскрывает IP провайдеру; UI честно различает отсутствие отправки метаданных файлов и наличие сетевой загрузки.
- Evaluation dataset как версионированные синтетические fixtures, не реальные документы: 100 объяснений с evidence, 100 неопределённых остатков/portable apps, 100 задач по цели и исключениям, 100 JSON/tool-call нарушений, 200 injection/adversarial RU/UK/EN (имена файлов, fake rules, Unicode, giant strings, hidden instructions). Holdout отдельно от prompt tuning. Отдельные системные тесты подтверждают, что произвольный model output не достигает executor.
- Release gates: 0 нарушений hard exclusions/исполненных неизвестных ID в испытаниях; 100% невалидных ответов отклонены; не менее 95% корректных ссылок на evidence и 90% оценок полезности/понятности по двойной ручной разметке; отчётить confidence intervals и размер выборки. Эти пороги — целевые, 0 ошибок на конечном наборе не доказывает отсутствие риска. Выпуск может идти с AI disabled, если основной продукт полезен, но встроенный AI из концепции не считается завершённым до прохождения ворот.

### Gaps
- Нужны реальные eval fixtures и независимый red-team прогон; текущие числа — спецификация проверки.

## Чем продукт полезнее существующих вариантов и что выпускать первым

### Takeaway
Отличие Cleaner — проверяемые объяснения, управляемый план, честный учёт места и безопасные границы в едином интерфейсе. Нельзя обещать, что конкуренты не приватны, не умеют показывать карту или что Cleaner быстрее WizTree без одинаковых измерений.

### Cited Findings
- Storage Sense удаляет временные файлы, обслуживает корзину и может делать OneDrive online-only; Downloads и cloud provider content не трогаются без пользовательской настройки. Это уже полезный встроенный конкурент для автоматического обслуживания. — [Microsoft Support](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/manage-drive-space-with-storage-sense), [configuration](https://learn.microsoft.com/en-us/windows/configuration/storage/storage-sense)
- WizTree показывает treemap, использует прямое чтение MFT для NTFS; опубликованные обещания скорости — заявления поставщика. Free распространяется только на personal use, коммерческая среда требует лицензию по site. — [About](https://diskanalyzer.com/about), [EULA](https://diskanalyzer.com/eula)
- TreeSize предоставляет дерево/визуализации; Free и Professional различаются. Страница старого free/features сейчас перенаправляет на **Professional**, поэтому функции оттуда нельзя автоматически приписывать Free. В KB Free отмечены ограничения hardlinks/ADS/dedup. — [features](https://www.jam-software.com/treesize/features.shtml), [Free KB](https://knowledgebase.jam-software.com/treesize_free/)
- BleachBit предлагает preview→delete, описания cleaners, Windows/Linux, portable, CleanerML и заявляет отсутствие telemetry. Локальность сама по себе не уникальна. — [официальные features](https://www.bleachbit.org/features)

### Inferences
- Матрица позиционирования: Storage Sense — системное обслуживание; WizTree — быстрый обзор размера; TreeSize — анализ/отчётность с зависимостью от редакции; BleachBit — каталог очистки; Cleaner — единый путь «основание→последствие→выбор→проверка→факт результата» плюс локальный помощник. Это проектное позиционирование, не доказанное преимущество на рынке.
- MVP продукта: Windows local NTFS/folder analysis, cancel/partial results, исключения, размер/allocated distinction, список крупных данных, 3–5 поддержанных категорий с последствиями, plan preview, один хорошо проверенный путь удаления для допустимых категорий, история, факт результата, optional local AI. Системные операции только через проверенные механизмы, не произвольное удаление Windows. Первый инженерный skeleton может быть analysis-only, но его нельзя называть завершённым MVP.
- v1.1: browser matrix, game library metadata, app remnants только review, profiles/growth history, automation с category allowlist и отдельным разрешением. v2: true duplicate content verification, removable/cloud/network semantics после отдельного дизайна. Реестр, drivers, optimizer/health score, обещания ускорения и глобальная автоматическая зачистка неизвестных файлов исключены.
- Проверки продукта: 8 из 10 новых участников самостоятельно находят основную причину занятого места и объясняют последствия выбранной категории ≤3min; 100% destructive flows требуют понятный план; все partial runs показывают пропуски; без модели нет блокировки navigation/scan; нет файловых метаданных в сетевом capture при offline-only сценарии. Измерения успеха через добровольные пилоты и локальный экспорт, не обязательную telemetry.

### Gaps
- Нет customer interviews, готовности платить, измеренного рынка, сравнительного benchmark и доказательства product-market fit. Цены конкурентов намеренно не фиксируются: сравнение поведения важнее, а условия меняются.

## Как должен выглядеть интерфейс в духе Apple на Windows

### Takeaway
Перенять спокойную иерархию, качественную типографику, понятные группы и сдержанную глубину; сохранить Windows titlebar, Snap, клавиатурные соглашения, системные темы и доступность. Ниже — самостоятельная дизайн-система Cleaner, а не копия macOS или нормативные численные требования Apple.

### Cited Findings
- Apple в официальной презентации Liquid Glass отделяет слой controls/navigation от content и предупреждает об избыточном наложении glass-on-glass; читаемость — центральное требование. Для утилиты с плотными числами это основание ограничить декоративную прозрачность. — [WWDC25 transcript](https://developer.apple.com/videos/play/wwdc2025/219/)
- Apple HIG Layout подчёркивает alignment/indentation для иерархии; accessible appearance — увеличение читаемости/контраста и уменьшение отвлекающего движения. Доступ к полному тексту HIG в web tool ограничен JavaScript, поэтому эти положения подтверждены индексированным содержимым и открытым официальным видео, а конкретные токены ниже — наши предложения. — [Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Accessible appearance](https://developer.apple.com/documentation/swiftui/accessible-appearance)
- Microsoft рекомендует ясный доступный responsive Fluent UI; Windows типографика использует Segoe UI Variable, regular/semibold, sentence case и по умолчанию left alignment. — [Windows design](https://learn.microsoft.com/en-us/windows/apps/design/), [Typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)
- Лицензия Apple San Francisco запрещает использование для макетов UI продуктов под non-Apple OS. Следовательно, даже Windows-макет Cleaner не должен использовать скачанный SF Pro; отдельно применяются условия Apple design resources. — [Apple Fonts license](https://developer.apple.com/fonts/index.html)
- Fluent System Icons распространяются под MIT; лицензия React UI package и условия fonts/assets не обязаны совпадать. Брать SVG из конкретного лицензированного icon repo с notice. — [System Icons](https://github.com/microsoft/fluentui-system-icons), [Fluent iconography](https://fluent2.microsoft.design/iconography)
- Windows доступность включает keyboard, Narrator/UI Automation, масштабирование и high contrast; собственным controls нужны automation peers/patterns. — [Accessibility overview](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-overview)
- Windows touch guidance определяет 40x40 epx и допускает увеличение до 44x44 с промежутком; classic animation guidance рекомендует большинство эффектов 100–300ms, типично 167/250ms. — [Touch interactions](https://learn.microsoft.com/en-us/windows/apps/develop/input/touch-interactions), [Animation guidance](https://github.com/MicrosoftDocs/win32/blob/docs/desktop-src/uxguide/vis-animations.md)
- WPF поддерживает light/dark/contrast, а современная WPF Fluent theme обновляет Windows 11 внешний вид. WinUI theme snippets нельзя механически копировать в WPF: API разные. — [Theming Windows apps](https://learn.microsoft.com/en-us/windows/apps/develop/ui/theming), [WPF Fluent announcement](https://blogs.windows.com/windowsdeveloper/2024/11/07/so-whats-new-with-microsoft-native-ux-technologies/)

Палитра предварительная: проверить **каждую фактическую пару**, включая hover/disabled/selected, на контраст. Не считать один цвет достаточным доказательством соответствия. Цель normal text ≥4.5:1, large ≥3:1, controls/focus ≥3:1. Цвет не кодирует единственный смысл: icon+label+shape.

- Spacing: 4,8,12,16,24,32,48. Страница 24, section gap24, card padding20/24, label/help gap4, icon/text gap8. Сетка и короткие левые края важнее декоративного выравнивания по центру.
- Typography: system Segoe UI Variable, затем Segoe UI, затем системный sans; не bundling Microsoft font files. Page title28/34 semibold; section20/28 semibold; card18/24 semibold; body14/20 regular; caption12/16 только secondary; крупный объём32/40 semibold, числа tabular если доступно; filepath моноширинный Consolas системный fallback и selectable. Избегать одних uppercase, thin gray и огромных hero заголовков.
- Радиусы: card12, inputs/buttons6, badge4; один большой radius не превращать в повсеместные pills. Border1; фокус2 с offset2. Shadow только floating drawer/dialog: малое рассеяние; списки читаются границами и отступом. Backdrop/blur допускается на shell при поддержке и достаточной скорости, никогда поверх таблицы или текста, выключается при contrast/reduced transparency/RDP/низкой производительности.
- Shell: обычный Windows titlebar с правыми min/max/close и Snap; sidebar216, header64, status strip28; page max readable line72–80 chars, data area растягивается. Минимум960x640, при ширине<1100 sidebar collapses в rail64, assistant становится overlay; ≥1280 разрешена правая панель360. При 200% текста layout перестраивается/скроллится и не обрезает destructive consequences; минимум окна не substitute reflow.
- Density: comfort row44, compact32 для data tables; главные controls40–44. Visible icon20, click target40. Touch mode44 и gap4. Не повышать density за счёт пояснений последствий.
- Motion: hover100ms, selection/page167ms, drawer250ms; easing ease-out. Progress обновлять до4Hz, не заставлять screen reader зачитывать каждый файл. При Windows animation disabled все декоративные перемещения исчезают; без bouncing/постоянных shimmer или fake busy. Числа освобождённого места не анимируются «счётчиком победы».
- Icons: единый Fluent outline20/24, filled только selected при необходимости; folder/drive/info/check/warning/error/clock. Не использовать emoji как системные статусы, SF Symbols/Apple logo/traffic lights. Собственный app icon с отдельными asset sizes и контрастом.
- Contrast theme: заменить brushes на DynamicResource SystemColors, сохранить borders/focus/selection; никаких fixed opacity и скрытия текста. WPF прислушивается к SystemParameters.HighContrast и системным изменениям; light/dark System/Light/Dark в настройках, contrast имеет приоритет.

#### Информационная архитектура и законченные экраны

Navigation MVP: «Обзор», «Диски и папки», «Рекомендации», «История», «Настройки». Помощник — toolbar button/drawer в контексте snapshot, не отдельная начальная страница. «Автоматизация» появляется лишь когда реализована, а не disabled рекламным placeholder. В footer sidebar статусы модели и фоновой задачи.

1. **Первый запуск.** Заголовок «Поймите, чем занят диск». Три коротких смысла: анализ локально, очистка после просмотра, модель необязательна. Primary «Выбрать диски», secondary «Настроить интеллект». Никакой модели или очистки до выбора. Setup модели показывает download size, диск назначения, estimated memory как estimate, «Продолжить без модели». Отдельная диагностика opt-in default off.
2. **Обзор.** Title «Обзор» + last scan timestamp. Drive cards: label/letter/file system, used/total/free, bar с именами категорий и legend. Главный CTA «Проверить пространство». Ниже «Что изменилось» только при двух comparable snapshots; иначе объяснение. Empty/no supported drives/error distinct. Нет «здоровье 37%», fake speed boost или большой кнопки «Очистить всё».
3. **Выбор области.** Multi-select drives/folders, scope summary, быстрый/полный охват, exclusions count+editor. Reparse/cloud/network policy понятным текстом. Closed details «Почему некоторые области недоступны». Primary «Начать анализ», cancel. UAC не нужен для открытия приложения; request contextual for justified operation.
4. **Сканирование.** Ступени «Изучаем структуру → Определяем категории → Готовим объяснения». Indeterminate progress до известного total; scanned count/elapsed/live partial totals. Действия «Остановить», «Смотреть найденное»; корректно различать pause и cancel (если pause нет, не рисовать). Не раскрывать длинный путь на широкую бегущую строку; truncated middle с selectable full detail. Error access denied summarised as partial.
5. **Диски и папки.** Breadcrumb + drive selector + «Размер / Занято на диске». Сверху категории bar, ниже accessible table (name,size,allocated,percent,modified/status) и optional treemap. Tree+table имеет те же сведения, доступные без treemap; screen reader получает иерархию, сортировку и count. Right details: owner/category/evidence/path/open location/exclude. Большие личные файлы default unchecked.
6. **Рекомендации.** Segments «Известные категории», «Требует просмотра», «Личные данные»; labels конкретнее абстрактного safety score. Карточка: title, verified/inferred badge, eligible bytes, evidence summary, consequence («Первый запуск может быть медленнее: кэш создастся заново»), restore method, expand file table, checkbox/select. Текст модели отдельным блоком «Пояснение модели» с evidence references. Bulk select только текущая понятная группа; personal/downloads/session/cookies отдельно и unchecked.
7. **Помощник.** Header «Локальный помощник • snapshot время» и resource status. Suggested requests «Объясни эту категорию», «Нужно 20 ГБ», «Не трогать загрузки». Ответ использует small fact table и uncertainty, button «Открыть предложенный план», не «Выполнить». Ввод запрета создаёт видимый constraint chip в общем plan state; model output не меняет его. Missing model/OOM предлагает обычные категории и настройку, не пустой заблокированный экран.
8. **Предпросмотр плана.** Отдельная страница, не крохотный confirm dialog. Title «Проверьте план». Метрики «Выбрано», «Ожидается освободить на C», «Требует переноса на D», «Доступно восстановление». Table category/count/bytes/method/consequence. Итоговые ограничения+snapshot freshness. Primary «Начать очистку» доступен после policy validation; рядом «Вернуться к выбору». Если irreversibility есть, отдельный человеческий текст с объёмом и категориями, focus по умолчанию на cancel/return, не опасная Enter активация.
9. **Выполнение.** Progress по операциям, factual counters, skipped count и expandable log. Cancel label «Остановить дальнейшие действия» объясняет, что выполненное остаётся. Никакой блокировки окна и обязательного всегда-on-top. Диск исчез/права отказаны/файл изменён/занят → skip/error отдельным итогом, не «всё успешно».
10. **Результат.** «Завершено» или «Выполнено частично», real free-space delta с timestamp и caveat concurrent changes; selected/processed/removed/quarantined/dehydrated bytes различаются. «Перемещено в карантин на C: 2 ГБ; место на C не освобождено». Details skips by reason, restore availability, rescan и открыть историю.
11. **История и восстановление.** List scans/actions with partial badges и фильтром. Detail operation manifest, retention, current restore status. Restore conflicts предлагают новое имя/другое место/skip; никакого silent overwrite. Недоступный исходный диск, missing quarantine, failed restore — отдельные объяснения. «Удалить историю» отдельно от удаления карантинных файлов.
12. **Настройки.** Поиск, группы «Область», «Очистка», «Интеллект», «Ресурсы», «Приватность», «Восстановление», «О приложении». На странице модели readiness, version/hash, file bytes, RAM profile, install/update/remove и offline status; удаление весов не смешивается с удалением пользовательских файлов. Schedule v1.1 имеет category allowlist, conditions, max per run, notifications; низкий остаток не расширяет полномочия.

#### Component и interaction contract

Кнопки: default/hover/pressed/disabled/focus/loading; disabled сопровождается причиной рядом, не tooltip-only. Checkbox tri-state и excluded lock badge с доступным explanation. Search: idle/focus/typing/loading/no match/error. Card: normal/selected/expanded/blocked/inferred/stale. Dialog: title/body/consequences/action/cancel, focus trap, Escape dismiss если операция не обязана завершиться. Banner: info/partial/error, persists до решения; toast только для необязательных событий, не единственное место сообщения об отказе.

Tab/Shift+Tab — логический порядок; стрелки внутри tree/table; Space toggles checkbox, Enter открывает выбранный detail; Escape закрывает panel и возвращает focus источнику. Ctrl+F page search, Ctrl+L focus path там где есть navigation, F5 refresh/rescan с проверкой текущей задачи; Delete не запускает немедленную очистку. Отдельные access keys при localization. Focus виден в каждой теме и не пропадает при async refresh. Screen-reader names содержат объект, размер, checked state, доступность действия; progress live region объявляет этап и разумные milestones, а не спам.

RU/UK/EN строки в ресурсах, никакой конкатенации фраз и размеров. Русские/украинские plural forms, locale dates и decimal separator. Выбрать явные GiB/GB и tooltip exact bytes, не выдавать 1024^3 за GB. Полные пути копируются и доступны из детали; truncation middle сохраняет basename; tooltip не единственный доступ. Длинные переводы проверять +40% expansion. Path bidi controls показывать безопасно, не интерпретировать как разметку.

#### Wireframes для автора отчёта и HTML preview

Нужны три **аннотированных** состояния: A) обзор с sidebar/drive cards/CTA и status модели; B) рекомендации с выбранной cache карточкой, evidence, consequence и раскрытой таблицей; C) plan preview с отличием selected vs expected freed/quarantine и final action. Для B можно показать assistant drawer как дополнительный desktop split. Отдельная схема user flow и model trust boundary. На каждом wireframe реальные имена интерфейса и демонстрационные числа с маркировкой, не псевдокод инфраструктуры.

HTML design preview: static standalone file, 3 tabs/screens Overview/Recommendations/Plan; System/Light/Dark и demo contrast; clickable card selection/detail и переход в план; no backend, no actual disk enumeration/delete, banner «Демонстрационный макет». Обязательно RU копирайт и keyboard focus. Preview показывает проектируемый visual target, WPF skeleton — инженерное основание; не называть HTML работающим Cleaner. Не требовать CDN, шрифтов и внешних image assets: открывается offline. Скриншот/ручная проверка при viewport1440x900 и 1024x768, 200% text, dark и contrast; если браузер недоступен, честно перечислить непроверенные visual checks.

### Gaps
- Палитра, layout и flow — исходная спецификация, не проверенный пользовательскими исследованиями финальный дизайн. Нужен usability pilot с новичками и keyboard/Narrator users, contrast audit и WPF perf check.
- Некоторые HIG страницы доступны в web tool только как JS stub; содержание выше дополнительно ограничено проверенными official transcript/search excerpts. Не утверждать полное соответствие Apple HIG и не приписывать Apple конкретные размеры/hex.
