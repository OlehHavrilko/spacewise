# Spacewise для Linux

Отдельное приложение Avalonia на .NET 10. Windows/WPF, Win32, NTFS и DPAPI не требуются. Это первая Linux-версия, а не полная копия Windows-интерфейса.

## Запуск

Распакуйте `Spacewise-linux-x64.tar.gz` в собственную папку и запустите:

```sh
chmod u+x Spacewise/Spacewise.Linux
./Spacewise/Spacewise.Linux
```

Нужны Linux с glibc и `statx`, графическая сессия X11 либо совместимость XWayland, стандартные зависимости Avalonia: X11, fontconfig, ICU, OpenSSL. Проверенная среда: Ubuntu 24.04, x86-64, WSL2, Xvfb. ARM64 можно собрать, но запуск на ARM64 пока не проверен. Не запускайте приложение через `sudo`.

## Что работает

- Отмена и ограничение обхода; логические размеры и выделенные блоки, inode/device, крупнейшие 100 файлов.
- Агрегаты папок и treemap верхнего уровня. Обход ограничен 500 000 файлами и 256 уровнями; агрегаты — 4096 папками. Неполный результат отмечается явно. Сумма логических размеров может учитывать несколько имён одного hardlink; это не оценка освобождаемого места.
- Отдельный Linux-каталог: миниатюры, pip, два кэша Mesa. Возраст — дополнительное условие известных кэшей, не самостоятельное основание очистки. Перед очисткой закройте приложения. Категории не выбираются автоматически.
- Сохраняемые исключения: абсолютные пути, с учётом регистра; действуют на анализ, предпросмотр и выполнение.
- Предпросмотр, подтверждение, карантин, восстановление без перезаписи существующего файла, отдельное подтверждение окончательного удаления.
- История последних 100 запусков сканирования. Она хранит итоги, а не полные снимки дерева.

## Данные и portable

По умолчанию данные находятся в `$XDG_DATA_HOME/spacewise` либо `~/.local/share/spacewise`. Кэши ищутся в `$XDG_CACHE_HOME` либо `~/.cache`. Относительные значения XDG игнорируются.

Создайте пустой `portable.flag` рядом с исполняемым файлом или передайте `--portable`: настройки, история и карантин будут в `Data` рядом с приложением. Данные защищены правами Unix (каталоги 0700, настройки 0600), **не зашифрованы**. Каталог данных с более широкими правами или символическими ссылками отклоняется. Файловая система должна поддерживать эти права.

Перемещение в карантин выполняется атомарным `renameat2(RENAME_NOREPLACE)` на том же файловом разделе. Между разделами операция откажет без удаления исходника (EXDEV); переносимого карантина на другом носителе пока нет. После перемещения место не освобождается: для этого нужно окончательно удалить файл из карантина. Автоматического удаления по сроку пока нет.

Манифест и SHA-256 записываются до перемещения. После перезапуска список восстанавливается по манифестам и имеющимся файлам. Изменённые файлы не удаляются окончательно и не восстанавливаются автоматически. Манифесты сохраняются после восстановления/удаления. При ошибке сохранения приложение сообщает о ней.

Символические ссылки не обходятся; очистка hardlink-файлов запрещена. `/proc`, `/sys`, `/dev` не сканируются. Папки системных компонентов не разрешены к очистке. ИИ, телеметрии, облачных запросов, служб и автозапуска нет. Операционная система может сохранять собственные сведения о запуске приложения.

## Сборка и тесты

```sh
dotnet build Spacewise.Linux.slnx -c Release
dotnet run --project tests/Spacewise.Tests.Linux -c Release
sh installer/build-linux.sh linux-x64
```

Графический smoke-тест (нужны Xvfb и зависимости X11):

```sh
xvfb-run -a ./Spacewise.Linux --smoke-test
```

Тесты создают только уникальные каталоги `spacewise-tests-*` в системной временной папке и удаляют их после проверки. Запускайте от обычного пользователя. Windows-тесты находятся в отдельном `Spacewise.slnx`.
