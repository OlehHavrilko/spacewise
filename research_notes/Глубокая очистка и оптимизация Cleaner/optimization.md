# Глубокая очистка и оптимизация Cleaner

Проверено 23 октября 2026. Это исследование проектируемых возможностей: команды **не запускались** на компьютере пользователя. Все объёмы и ускорения должны определяться на конкретном ПК. Документ дополняет прежнее исследование и расширяет продукт до мощного каталога реальных действий, не ограничивая его обзором диска.

## Какие действия действительно освобождают место

### Takeaway
Большие выигрыши дают не только temp: версии компонентов Windows, предыдущая Windows, developer/container caches, установленные игры и приложения, локальные облачные копии и файл гибернации. Но это разные типы операций — удаление, сжатие, перенос, dehydration и изменение конфигурации — с разными последствиями и восстановлением.

### Cited Findings

#### Windows и системное хранение

- **Component store.** Поддержанный анализ: `Dism.exe /Online /Cleanup-Image /AnalyzeComponentStore`; очистка: `Dism.exe /Online /Cleanup-Image /StartComponentCleanup`. Последняя удаляет предыдущие версии обновлённых компонентов сразу, без 30-дневной отсрочки планового задания и без его часового ограничения. Сама папка WinSxS вручную не удаляется. `... /StartComponentCleanup /ResetBase` удаляет все superseded versions и делает невозможным удаление **всех уже установленных update packages**, но не будущих. Это отдельная мощная необратимая опция, не скрытая часть обычной очистки. — [Clean Up WinSxS](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/clean-up-the-winsxs-folder), [DISM servicing reference](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/dism-operating-system-package-servicing-command-line-options)
- **Windows.old.** Официальный путь: Settings → System → Storage → Temporary files → Previous version of Windows → Remove files. Удаление уничтожает возможность возврата к предыдущей версии; штатная предыдущая копия обычно удаляется автоматически спустя 10 дней после обновления. Explorer folder bytes — не независимая гарантия reclaim. Для первой реализации предпочтительна управляемая передача в Windows UI, а не захват ownership каталога. — [Delete previous Windows](https://support.microsoft.com/en-us/windows/deployment/install-upgrade/delete-your-previous-version-of-windows)
- **Native cleanup.** `cleanmgr` документирует `/sageset:n` (сохранить набор выбранных обработчиков) и `/sagerun:n` (исполнить выбранный профиль). `/d` с `/sagerun` не используется: последний перебирает диски. Следовательно, нельзя обещать per-volume scope простым добавлением `/d C:`. Продукт должен показывать real scope и учитывать состояние профиля, а не наугад редактировать undocumented StateFlags. — [cleanmgr](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cleanmgr)
- **Корзина.** `SHQueryRecycleBinW(root, SHQUERYRBINFO)` возвращает количество и размер для диска; `SHEmptyRecycleBinW(hwnd, root, flags)` очищает выбранный диск. Empty/null root во втором API затрагивает корзины всех дисков. Флаги позволяют suppress confirmation/progress, но наличие API не отменяет контекст пользовательского плана. — [query](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryrecyclebinw), [empty](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shemptyrecyclebinw)
- **Гибернация.** `powercfg /a` проверяет доступные состояния; `/hibernate on|off`, `/h /type full|reduced` — документированные изменения. Full hiberfile поддерживает hibernate/hybrid sleep/Fast Startup; reduced — только Fast Startup. В документации default размеры full40% и reduced20% physical RAM, но пользовательские и реальные размеры могут отличаться. Отключение hiberfile убирает использующие его режимы. — [powercfg](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options), [power states](https://learn.microsoft.com/en-us/windows/win32/power/system-power-states)
- **CompactOS.** `compact.exe /CompactOS:query`, `...:always`, `...:never` — запрос, сжатие и распаковка OS binaries. `never` возвращает non-Compact. Windows servicing умеет обновлять сжатые файлы. Это изменение способа хранения, а не удаление мусора. — [compact](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/compact), [Compact OS](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/compact-os)
- **Reserved storage.** DISM предоставляет `/Online /Get-ReservedStorageState` и `/Online /Set-ReservedStorageState /State:Enabled|Disabled`. Доступно начиная с Windows10 2004. Изменение запрещено, когда reserve занят обслуживанием: ждать завершения, не обходить ошибку. Наличие резерва не означает целиком лишние пользовательские данные. — [DISM storage reserve](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/dism-storage-reserve), [cmdlet constraints](https://learn.microsoft.com/en-us/powershell/module/dism/set-windowsreservedstoragestate)
- **VSS/restore.** `vssadmin delete shadows /for=<volume> /oldest` либо `/shadow=<ShadowID>` удаляет client-accessible shadow copy. Восстановление удалённой shadow copy невозможно; пропадают связанные previous versions/restore points. Не все VSS contexts доступны этой команде. Нельзя silently заменить отказ на более широкое `diskshadow delete all`. — [vssadmin](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/vssadmin-delete-shadows)
- **Pagefile.** Требуемый размер определяется peak commit и crash-dump configuration; для dump обычно нужен pagefile/специальный dump file подходящего размера. Универсальное «отключить pagefile при большом RAM» не следует из документации и ухудшает поддерживаемость/commit headroom. — [pagefile sizing](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/how-to-determine-the-appropriate-page-file-size-for-64-bit-versions-of-windows)
- **Cloud.** OneDrive «Free up space» делает локальную копию online-only; это не Delete. Удаление файла в OneDrive удаляет его из OneDrive и со всех устройств. Online-only требует Internet для последующего открытия; Always keep on this device занимает локальное место. — [OneDrive Files On-Demand](https://support.microsoft.com/en-us/onedrive/save-disk-space-with-onedrive-files-on-demand-for-windows)
- Storage Sense обрабатывает временные файлы/корзину/локальную cloud доступность по настройкам; Downloads/cloud content по умолчанию не трогает без настройки пользователя. — [Storage Sense](https://support.microsoft.com/en-us/windows/experience/storage-filemanagement/manage-drive-space-with-storage-sense)
- **Capabilities/features.** Поддержанные команды `DISM /Online /Get-Capabilities`, `/Get-CapabilityInfo /CapabilityName:<exact>`, `/Remove-Capability /CapabilityName:<exact>`; для features — `/Get-Features`, `/Get-FeatureInfo /FeatureName:<exact>`, `/Disable-Feature /FeatureName:<exact>` и при поддержке `/Remove` для payload. Реинсталляция removed payload может требовать Windows Update/источник. Нельзя удалять display/input language без учёта текущего языка и зависимостей. — [Capabilities](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/dism-capabilities-package-servicing-command-line-options), [enable/disable features](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/enable-or-disable-windows-features-using-dism), [language settings](https://support.microsoft.com/en-us/windows/hardware/input-devices/manage-the-language-and-keyboard-input-layout-settings-in-windows)
- **Uninstall.** `winget uninstall --id <exactID> --exact` — штатный каталогизированный вариант при наличии WinGet; сам uninstall может вызвать vendor installer/dialog/reboot. Settings → Apps — официальный альтернативный путь. Удаление каталога Program Files не эквивалентно uninstall. — [WinGet uninstall](https://learn.microsoft.com/en-us/windows/package-manager/winget/uninstall)

#### Developer и игровые данные

- **NuGet.** `dotnet nuget locals all --list` перечисляет реальные cache locations; granular clear для `http-cache`, `temp`, `plugins-cache`, `global-packages`, либо `all --clear`. Папка global-packages содержит используемые при сборке пакеты; очистка потребует restore и возможного сетевого доступа. Старые private-feed версии могут оказаться недоступны. — [NuGet locals](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-nuget-locals), [cache management](https://learn.microsoft.com/en-us/nuget/consume-packages/managing-the-global-packages-and-cache-folders)
- **npm.** Кэш self-healing; его очистка нужна для возврата места, а не регулярного «лечения». `npm cache verify` проверяет/обслуживает; `npm cache clean --force` допускает очистку. Удаление `node_modules` проекта — отдельное действие, не этот cache command. — [npm-cache](https://docs.npmjs.com/cli/cache/)
- **pip.** `py -m pip cache dir|info|list|remove|purge`; `purge` очищает wheel и HTTP caches. Требуется выбрать правильный interpreter/user context; это не uninstall packages и не удаление venv. — [pip cache](https://pip.pypa.io/en/stable/cli/pip_cache/)
- **Docker.** `docker system df --format json` и `docker system df -v` дают daemon accounting, shared и unique layers. `docker builder prune` выбирается для build cache; `docker system prune` затрагивает stopped containers, unused networks, dangling images и build cache. `-a` расширяет images, `--volumes` включает anonymous volumes. Stopped container может иметь единственную копию важных данных; «unused» не означает «не нужен пользователю». — [system df](https://docs.docker.com/reference/cli/docker/system/df/), [system prune](https://docs.docker.com/reference/cli/docker/system/prune/)
- **Docker VHD.** На Windows расположение данных зависит от backend и Disk image location settings; для backup VM должен быть полностью остановлен. Содержимое volumes не включается автоматически в image commit. Нельзя считать `docker_data.vhdx` временным файлом и удалять целиком ради cleanup. — [Docker backup](https://docs.docker.com/desktop/settings-and-maintenance/backup-and-restore/)
- **WSL.** ext4.vhdx имеет максимум virtual capacity, который не равен занимаемым Windows bytes. `wsl --list --verbose` перечисляет distributions; `wsl --shutdown` останавливает WSL VM. `wsl --unregister <Distribution>` — **полное удаление данных distro**, не cleanup. Sparse VHD описывался Microsoft как experimental/opt-in; старый блог не доказывает одинаковое поведение всех актуальных версий. — [disk space](https://learn.microsoft.com/en-us/windows/wsl/disk-space), [basic commands](https://learn.microsoft.com/en-us/windows/wsl/basic-commands), [historical sparse VHD](https://devblogs.microsoft.com/commandline/windows-subsystem-for-linux-september-2023-update/)
- **Build artifacts.** MSBuild Clean может содержать пользовательские targets, включая CustomClean. Вызов `dotnet clean` на недоверенном найденном проекте потенциально исполняет код проекта; это не read-only распознавание и не универсальная безопасная операция. — [custom build process](https://learn.microsoft.com/en-us/visualstudio/msbuild/how-to-extend-the-visual-studio-build-process), [MSBuild overview](https://learn.microsoft.com/en-us/visualstudio/msbuild/build-process-overview)
- **Steam.** Официальный support описывает перемещение через Steam Settings → Storage и отдельную процедуру переноса установки. Данные/сохранения могут находиться в разных местах; перемещать библиотеку предпочтительно механизмом launcher. Проверка получила индексированный текст официального FAQ, но open body вернул только изображение: полноценный workflow требует version-specific теста клиента. — [Steam Support](https://help.steampowered.com/en/faqs/view/4BD4-4528-6B2E-8327)

### Inferences

#### Практический каталог действий и три уровня

Ниже решения команды, основанные на документах выше; «обратимо» означает обратимость конфигурации/возможность пересоздать данные, а не гарантию возврата удалённых исходных bytes.

| Действие | Trigger/preflight | Реальный выигрыш и цена | Уровень продукта |
|---|---|---|---|
| Известные app/browser caches | версия приложения, подтверждённые пути, app закрыт, keep cookies/sessions | bytes исходного тома; кэш скачивается/строится снова | обычный профиль, granular правила |
| Temp/log/crash dumps | category owner, возраст+lock checks, retention, active troubleshooting exclusion | может быть крупно; утрата диагностических материалов | обычный/расширенный по категории |
| Recycle Bin | query выбранного root+просмотр items | итоговый permanent delete, нельзя обещать undo | явный пункт плана, без автоселекции всей корзины |
| DISM StartComponentCleanup | supported OS, elevated broker, analyze, servicing state | только фактический delta; operation может долго идти | глубокий штатный профиль |
| DISM ResetBase | отдельный opt-in после stable-update period по выбору человека | потенциально больше; потеря uninstall текущих updates | экспертный destructive, не по расписанию |
| Windows.old | обнаружен upgrade rollback, Windows UI eligibility | может быть одной из крупнейших находок; потеря Go Back, проверить личные данные | отдельный destructive пункт, Windows UI adapter |
| NuGet/npm/pip caches | tool/version/user paths, builds idle, public/private feeds availability | обычно многократно используемые bytes; следующие restore/download медленнее, offline builds могут перестать работать | dev preset, granular categories |
| Docker build cache | выбранный **local** daemon/context, active builds отсутствуют, inventory | daemon reclaim и host-volume reclaim отдельно; сборки медленнее | dev preset после review |
| Docker images/containers/volumes | отдельные IDs, зависимости, backup | может быть большой выигрыш; удаление единственной копии container/DB data | expert explicit per-object, volumes не default |
| WSL внутренний cleanup/compaction | distro+version, backup, quiesce, preflight maintenance adapter | first Linux free bytes, then **измеренный** host volume gain | поздний проверенный adapter, не универсальный raw VHD hack |
| Games/apps uninstall | конкретное приложение/игра, launcher/vendor uninstall | большой выигрыш возможен, переустановка и сохранения отдельно | page «Приложения и игры», review |
| Move game/library | выбран target free capacity, launcher-supported move | frees C и occupies D, общий выигрыш около нуля | обратимый перенос, отдельная метрика |
| Cloud Free up space | confirmed sync, provider feature, no pending uploads/unsynced/pinned exception | frees local allocated, cloud copy остаётся; offline access теряется | отдельный dehydration action, не Delete |
| Hiberfile full→reduced | `powercfg /a`, current allocated bytes и power usage intent | сохраняет Fast Startup, убирает hibernate/hybrid | advanced reversible config |
| Hiberfile off | требуется explicit use-case/user выбор | освобождение measured hiberfile, потеря зависимых power states | advanced reversible config, laptop consequences |
| CompactOS always | state query, supported OS, свободное место для работы/отката, нагрузка/питание | сохранение данных через compression; время/CPU tradeoff, исход неизвестен без измерения | advanced reversible storage optimization |
| Optional feature/capability/language remove | exact installed ID, deps, selected app needs, reinstall source | payload bytes если реально удалены; возможны network/reboot | advanced review, никаких blanket debloat |
| Reserved storage disable | только поддержанный build, servicing idle, reserve state | изменение резерва не обещает гарантированные GB; снижает cushion обновлений | экспертная настройка, по умолчанию оставить |
| VSS oldest/selected snapshot | inventory client-accessible ID/time/dependencies | actual delta; исчезновение recovery point | экспертный destructive, поштучно; exclude all/quiet blanket |
| Pagefile size/disable | peak commit и dumps требуют отдельного анализа | риск commit exhaustion/dump loss | не обычная очистка; оставить system-managed, review info only |

Один общий подход: не присваивать категории фиксированный «обычно освободит 5–20 ГБ». Показать обнаруженный allocated/eligible объём или «оценка доступна после анализа», потому что ноль — нормальный результат чистой системы. Реальные крупные категории ранжировать **по найденному объёму и цене решения**, а не по маркетинговому рейтингу. Если задача освободить 40ГБ и caches дают 1ГБ, показать игры/перенос/OneDrive/гибернацию/Windows.old при наличии, с явными компромиссами; не заявлять, что система «очищена максимально», пока это только temp.

#### Execution adapters, а не произвольный shell

Список выше — справочник **внутренних** adapter templates. Приложение вызывает verified absolute system binary/native API, struct arguments, no shell concatenation, no PATH-resolved executable из текущего каталога; ни пользователь, ни модель не вводят произвольные команды. Tool binaries разработчика проверяются на путь/подпись/контекст, и выполняются обычным пользователем: повышенные права нужны только конкретным системным операциям. Не запускать npm/pip/project scripts из любой найденной папки, где могут находиться config/plugins/подменённые executable; отдельно проектировать isolated working dir, per-user environment, supply-chain checks.

State machine native operation: Detected → Eligible → Proposed → ApprovedPlan → Preflight → Running → Completed|Partial|NeedsReboot|Failed|CancelledBeforeStart. Servicing не kill-ить посреди работы ради красивой кнопки отмены; проверять контракт конкретной операции, «Остановить очередь» может запретить только следующие шаги. Потерянный UI после crash не означает повторять необратимую команду: reconcile с native state/journal.

Adapter record: stable rule/action ID+version, platform prerequisites, detection evidence, estimate type/exactness, elevation requirement, execution scope, preconditions, procedure/native API, mutually exclusive actions, irreversibility, restore/compensating config, offline/network/reboot notes, known error mapping, success proof and telemetry schema. Нужен конфликт graph: WinSxS через DISM и native cleanup не считать дважды; Docker shared layers не суммировать как независимые; hibernation reduction и off взаимоисключающие; cloud move/delete и dehydration несовместимы.

### Gaps
- Нет проверенного универсального публичного structured API «исполнить произвольную категорию Storage Sense с exact preview». Наличие Settings URI — навигация, не headless cleanup. `cleanmgr` профиль не гарантирует изолированный scope.
- CfDehydratePlaceholder современный endpoint недоступен в web tool; нельзя обосновать им универсальный cross-provider adapter. MVP cloud — provider/Windows UI integration, не прямой API claim; отдельное испытание SDK/preconditions перед автоматизацией.
- Нельзя описывать WSL compaction как всегда доступный Optimize-VHD на всех Home/Pro/WSL versions. Нужна versioned implementation и backup/recovery; официальный disk-space guide сам по себе не обещает очистку host VHD после любого удаления.
- Не изучены отдельные Xbox/Epic/Battle.net APIs: использовать launcher UI с точной версией, не выдумывать поддержанный общий move API.

## Как оптимизировать систему и измерять эффект

### Takeaway
Настоящая оптимизация — отдельные наблюдаемые задачи: корректное обслуживание носителя, уменьшение реально ненужной автозагрузки/фоновой активности и выбор компромиссов хранения. Очистка диска, ускорение запуска, RAM pressure и FPS — разные метрики, которые не складываются в «процент здоровья».

### Cited Findings
- `Optimize-Volume` без специальных операций выбирает действие по типу: HDD analyze/defrag, SSD с TRIM retrim, unknown/removable FAT/SSD без TRIM — no-op; thin/dynamic configurations имеют другие комбинации. Explicit `-Analyze`, `-ReTrim`, `-Defrag` поддержаны; CIM `MSFT_Volume.Optimize` позволяет structured method. Использовать выбор Windows, не повторяющийся blanket defrag для всех SSD. — [Optimize-Volume](https://learn.microsoft.com/en-us/powershell/module/storage/optimize-volume), [MSFT_Volume Optimize](https://learn.microsoft.com/en-us/windows-hardware/drivers/storage/optimize-msft-volume)
- Windows Settings/Task Manager позволяют менять startup apps; набор включает registry Run и Startup folders, но не все фоновые активности сводятся к startup switch. — [Microsoft startup guide](https://support.microsoft.com/en-us/windows/experience/startup-boot/configure-startup-applications-in-windows)
- Background activity settings применимы не ко всем приложениям; enterprise activity policies документированы для UWP, не как глобальный setter любых Win32 processes. «Power optimized» управляет периодическими обновлениями/уведомлениями с энергокомпромиссом. — [Windows background apps](https://support.microsoft.com/en-gb/windows/privacy/windows-background-apps-and-your-privacy), [enterprise controls scope](https://learn.microsoft.com/en-us/windows/application-management/enterprise-background-activity-controls)
- Документированы переходы `ms-settings:startupapps`, `ms-settings:storagesense`, `ms-settings:appsfeatures` и другие страницы. URI открывает Settings, не предоставляет произвольную запись внутренних Windows databases. — [Launch Settings](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings)
- `GetDiskFreeSpaceExW` различает bytes available caller (quota), total bytes и total free bytes; эти величины нужно хранить отдельно, а root стабильного тома — не подменять буквой. — [API](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw)
- Старый Microsoft registry-cleaner policy URL сейчас перенаправляет на общую support page; search index содержит прежнее «Microsoft does not support…». Не представлять недоступный текст как актуальную полностью прочитанную политику. Более старое официальное Microsoft Press руководство прямо предупреждает об indiscriminate registry deleting и поломках. — [текущий редирект старой политики](https://support.microsoft.com/sl-si/topic/microsoft-support-policy-for-the-use-of-registry-cleaning-utilities-0485f4df-9520-3691-2461-7b0fd54e8b3a), [Microsoft Press](https://download.microsoft.com/download/7/3/8/7381E0E8-CE72-4366-9849-13B2BAFBBA3C/Microsoft_Press_ebook_Windows_10_Tools_Mobile-Only.pdf)

### Inferences
- TRIM сообщает storage об уже ненужных блоках, а не удаляет ещё пользовательские файлы. Значение «trimmed bytes» нельзя выдавать за newly free filesystem bytes. Дефрагментация переставляет данные, не является источником обещанных десятков GB.
- Не делать registry cleaners, RAM/standby-list purges, disable Defender/updates, blanket services/scheduled-tasks shutdown, отключение системного pagefile, удаление DriverStore/Installer/WinSxS вручную или gaming boost. Нет найденного первичного обоснования, что эти универсальные действия дают стабильный выигрыш пользователю. Это ограничения продукта, а не запрет человеку на продвинутые настройки.
- Раздел «Автозагрузка и фон»: inventory startup source, signed publisher, path, enabled state, observed runtime/CPU/IO и запуск при входе. Не обвинять неизвестный файл в вредоносности по подписи/имени. Первоначально «Открыть автозагрузку Windows» с возвратом и re-detect change; genuine first-party setter реализовать только после проверки exact mechanism, backup previous state и rollback. Task Manager high startup impact считать reported observation, не обещанием «ускорится на 40%».
- Background review: дать пользователю выбрать sync/chat/game launcher и объяснить утрату notifications/sync; управлять штатным app setting, не forcibly kill/disable service без знания продукта. Для неуправляемого Win32 показать «настроить в приложении», не фиктивный универсальный switch.
- Power tuning: оставить Balanced/Windows-managed default; режим максимальной производительности не считать бесплатным ускорением — расход/тепло/батарея. `powercfg /energy` или `/batteryreport` — diagnostics при необходимости, не очистка. ИИ может объяснять наблюдения, не сам менять power configuration.
- Performance validation: до/после повторить одинаковую задачу при сходных power/thermal/background условиях минимум3–5 раз, p50/p95 и variability; отдельно reboot/login-to-ready, launch конкретного приложения, idle CPU/IO за фиксированное окно, peak commit/hard faults при конкретной нагрузке. Если данных нет — «настройка изменена; влияние на скорость не измерялось». После cache cleanup cold launch может быть медленнее; измерять также повторный warm run, не выбирать удобный результат. FPS только отдельный reproducible game benchmark, по умолчанию не измеряется и не обещается.

#### Accounting contract для реального результата

До действия фиксировать volume GUID/serial, timestamp, totalFree, availableToCaller, quota context; snapshot category estimates, allocated bytes, shared/hardlink handling. После завершения/settling native operation повторить на том же volume ID. `observedFreeDelta = totalFreeAfter-totalFreeBefore` может быть отрицателен, потому что одновременно пишет Windows/приложение; не обрезать до нуля. Отдельно хранить `executorReportedReclaimedBytes`, `removedLogicalBytes`, `removedAllocatedEstimate`, `dehydratedAllocatedBytes`, `compressedDeltaEstimate`, `movedSourceBytes`, `quarantineDestinationBytes`, `observedAvailableDelta`.

Для C→D перенос/карантин: C gained и D consumed оба показываются, overall net не считать экономией. Quarantine C→C не освобождает C. Recycle C→C тоже не final free. Docker native reclaim на Linux filesystem не host-volume reclaim: показать оба и «Windows место пока не вернулось», если VHD не shrink. Dedup/shared layers/hardlinks требуют unique allocation — сумма logical sizes не основание успеха. Reserve reconfiguration и compression отличаются от delete, и UI говорит именно это.

Attribution: запустить по одному category adapter, делать интервальные measurements; фоновая запись всё равно мешает идеальной причинной оценке. Отчёт называет delta наблюдаемым, а native result — отчётом операции. При reboot-required дать preliminary и later verified result, без финальной победной цифры до проверки. Цель пользователя должна быть per-volume: «На C доступно не менее X GiB», проверяется после выполнения; перенос на D может достичь цели без overall deletion.

### Gaps
- Нет контрольных замеров на ПК, поэтому ни один startup/CPU/FPS/battery gain не доказан. Точные counter/ETW провайдеры и права нужно специфицировать implementation spike, не выдумывать интерфейс measurement из одного понятия WMI.
- Native servicing estimates/available APIs и cancellation semantics version-specific. Нужно тестировать mock+Windows VMs со servicing-in-progress/pending reboot/full disk/UAC denial и реальными app versions.

#### Дополнение навигации и экранов

#### Реальный roadmap и качество

Сильное первое рабочее расширение: проверенные temp/browser rules, корзина по root, dev cache probes и granular clear, DISM analyze+StartComponentCleanup, installed app/game size review и Windows/launcher handoff. Это уже реальная экономия, без ожидания всех risky adapters. Второй этап — versioned Docker/WSL, cloud provider dehydration и config rollback, compression/hibernation. Экспертные ResetBase/VSS/features доступны после VM regression and recovery tests. Анализ-only skeleton остаётся только skeleton.

Мощность измеряется verified supported rule coverage реальных установленных apps, найденным unique eligible allocation, долей successful target-per-volume runs, skip/error/rollback correctness и фактическим sustained net benefit после 7/30 дней с согласия пилотных пользователей. Большой каталог без regression fixtures вреднее маленького. Каждый cleaner rule должен иметь fixture (positive/negative/locked/changed/excluded/reparse/cloud), app version support и выключение при несовместимости. «Как у BleachBit» не означает копировать правила/базу без анализа соответствующей лицензии и совместимости.
