## 1. Разбор UI конкурентов: что работает и какие dark patterns избегать

### Takeaway
Лучшие анализаторы (WizTree, TreeSize, WinDirStat, DaisyDisk) сочетают дерево/таблицу с картой пространства и быстрый скан NTFS через MFT; лучшие чистильщики (BleachBit, Storage Sense) — описание каждой категории, чекбоксы, обязательный preview и явные сроки. Худшие практики — бандлинг, раздутые «счётчики мусора» и fake-scan/«здоровье ПК» — Cleaner должен явно отвергнуть.

### Cited Findings
- WizTree: дерево папок вместе с treemap в одном окне («tree view with tree map»), отдельный режим «Find the largest files» — [WizTree](https://diskanalyzer.com/).
- WizTree на NTFS читает Master File Table напрямую, минуя обход ФС через Windows API; для сканирования папок по умолчанию используется Windows API, с v4.20 есть опция MFT для папок (Ctrl при старте скана) — [About WizTree](https://diskanalyzer.com/about); [Luis Llamas](https://www.luisllamas.es/en/wiztree/). Заявление «46x быстрее WinDirStat» — маркетинг производителя без независимого бенчмарка — [diskanalyzer.com](https://diskanalyzer.com/).
- TreeSize: Explorer-подобный интерфейс, диаграммы Pie, Bar и Treemap, детальная разбивка папок; анализ локальных дисков, сетевых шар и облака — [TreeSize](https://www.jam-software.com/treesize).
- WinDirStat (современная версия): позиционирует себя как «disk usage analyzer and cleanup assistant»; сканирует несколько папок, дисков, сетевых шар, MTP-устройства; ускоренный NTFS-скан при повышении прав (elevate) — [WinDirStat](https://windirstat.net/).
- DaisyDisk: кольцевая (sunburst) интерактивная карта, «neat, colorful rings» для погружения в папки; v4 — плоский дизайн, скан до 20x быстрее, меньше памяти (цитаты прессы на сайте) — [DaisyDisk](https://daisydiskapp.com/).
- CleanMyMac Space Lens: карта хранилища в виде «пузырей» разного размера; скан основного диска, других томов или папки; сортировка папок по размеру; системные файлы защищены от удаления — [MacPaw KB Space Lens](https://macpaw.com/support/cleanmymac/knowledgebase/space-lens); [iMore](https://www.imore.com/cleanmymac-x-adds-space-lens-help-you-see-and-clear-out-unwanted-files-taking-precious-disk-space); [MacPaw news](https://macpaw.com/news/cleanmymac-space-lens-revamp).
- CleanMyMac 5 продаётся как «Smart & effortless Mac care», «Five routines», обещает «reclaim GBs of space» — маркетинговая подача «ухода» вместо фактов — [CleanMyMac](https://macpaw.com/cleanmymac).
- BleachBit UX-цикл: «read the descriptions, check the boxes you want, click preview, and click delete»; нет рекламы, телеметрии, бандлинга; CLI; пользовательские чистильщики на CleanerML; опции shred и перезаписи свободного места — [BleachBit Features](https://www.bleachbit.org/features).
- Windows Storage Sense: по умолчанию срабатывает при нехватке места, удаляет временные файлы; Корзина чистится по сроку; Downloads и OneDrive не трогаются, пока пользователь не настроит; пороги в днях («if they have been there for over», «haven't been opened for more than»); работает только на системном диске C: — [Microsoft Support: Storage Sense](https://support.microsoft.com/en-us/windows/manage-drive-space-with-storage-sense-654f6ada-7bfc-45e5-966b-e24aded96ad5).
- CCleaner: в 2018 при установке ставился Avast Antivirus без разрешения; в 2020 Windows Defender пометил бесплатную версию как PUA из-за бандлинга; Piriform сделал установку третьих программ опциональной — [Wikipedia: CCleaner](https://en.wikipedia.org/wiki/CCleaner).
- PrivaZer фокусируется на «следах» (traces), включая следы в свободном месте; сам признаёт, что минимум следов на C: будет всегда, т.к. система постоянно создаёт/удаляет временные файлы — [PrivaZer](https://privazer.com/en/).

### Inferences
- Шаблон «дерево/таблица + карта рядом, синхронное выделение» (WizTree, WinDirStat, TreeSize) — базовый для экрана «Диски и папки».
- Цикл BleachBit «описание → чекбокс → preview → delete» совпадает с концепцией «план до действия»; Cleaner добавляет к нему последствия, восстановимость и разницу «объём файлов vs реально освободится».
- Storage Sense задаёт ожидания пользователей Windows для автоматизации: пороги «N дней», «только при нехватке места», «по умолчанию личное не трогаем». Коридор Autopilot стоит строить в тех же терминах.
- Dark patterns, которые Cleaner явно не делает: (а) «индекс здоровья»/оценка ПК; (б) суммарный «мусор» с включением кэшей, которые немедленно пересоздаются, и пересчётом следов «в свободном месте»; (в) красные тревожные баннеры «Ваш ПК в опасности»; (г) бандлинг и предвыбранные доп. программы; (д) предвыбор всех категорий по умолчанию; (е) «уход/рутины» без числа реально освобождённого места.
- PrivaZer-аргумент «следы всегда есть» показывает, почему нельзя считать мусором всё, что найдено: счётчик должен включать только объекты, которые пользователь может включить в план.

### Gaps
- SpaceSniffer и Wise Disk Cleaner: первоисточники не получены в этой сессии; детальный разбор их UI не подтверждён.
- CCleaner «Health Check» и CleanMyMac «Assistant»: не найдено первоисточника с описанием механики и критикой; утверждения о «завышенных счётчиках» у конкретных продуктов не проверены, использовать только как общий принцип.
- FTC-дело Restoro/Reimage (fake scans) — страница вернула 404; ссылку на прецедент нужно перепроверить отдельно.

## 2. Визуализация пространства: treemap vs sunburst vs списки; производительность; доступность

### Takeaway
Treemap (squarified) — лучший обзор крупных объектов при плотной упаковке; sunburst хорош для иерархии и навигации «вглубь», но тратит площадь; таблица/дерево обязательна как основной и доступный вид. Для миллионов узлов рисовать агрегаты, а не файлы.

### Cited Findings
- Критерии тайлинга treemap: малое соотношение сторон (близко к 1, «fat objects» легче воспринимать), сохранение порядка, стабильность при изменении данных; эти свойства в обратной зависимости — оптимизация aspect ratio ухудшает предсказуемость порядка — [Wikipedia: Treemapping](https://en.wikipedia.org/wiki/Treemapping).
- Squarified-алгоритм (Bruls, Huizing, van Wijk) оптимизирует aspect ratio ценой стабильности — [Wikipedia: Treemapping](https://en.wikipedia.org/wiki/Treemapping).
- TreeSize даёт пользователю выбор Pie/Bar/Treemap — [TreeSize](https://www.jam-software.com/treesize); DaisyDisk — sunburst; Space Lens — пузыри — [DaisyDisk](https://daisydiskapp.com/); [MacPaw KB](https://macpaw.com/support/cleanmymac/knowledgebase/space-lens).
- Контрастные темы: жёстко заданные цвета ломают контраст; использовать ресурсы темы и системные цвета — [Microsoft: Contrast themes](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/high-contrast-themes).

### Inferences
- Рекомендация для Cleaner: основной вид — виртуализированная таблица-дерево (`TreeView`/`DataGrid` с `VirtualizingStackPanel`, `VirtualizationMode=Recycling`) с колонками «Размер», «На диске», «% родителя» (inline-бар), «Файлов», «Изменено», «Последний запуск/доступ», «Категория», «Владелец-приложение». Карта — вторичный вид рядом (сплиттер), синхронное выделение.
- Treemap — squarified, но с «замороженным» порядком при обновлении (иначе плитки прыгают между сканами). Для истории роста лучше слайс-и-дайс/ordered вариант или bar list, потому что стабильность важнее aspect ratio.
- Sunburst — опциональный режим «Глубина» для навигации 3–5 уровней; не для сравнения размеров.
- Производительность: рисовать только узлы ≥ ~1 px² площади, объединять мелкие в «Остальное (N объектов)»; ограничить глубину рендера 3–4 уровнями от текущего корня; рендер через `DrawingVisual`/`WriteableBitmap`, а не тысячи `UIElement`; hit-test по пространственному индексу. Это инженерные выводы, а не цитаты.
- Цвет по категории (Система, Приложения, Игры, Разработка, Личные, Неизвестно) + узор/подпись, т.к. смысл не должен передаваться только цветом (требование §9 концепции). В High Contrast — заливки из системных цветов, границы плиток обязательны.
- Доступность: treemap для Narrator — `AutomationPeer` с ролью дерева/списка, фокус клавиатурой по плиткам (стрелки — соседи, Enter — вглубь, Backspace — вверх), объявление «Папка Steam, 214 ГБ, 23 % диска D». Таблица — эквивалентный альтернативный вид, переключатель «Карта / Таблица» запоминается.

### Gaps
- Не найдено опубликованных бенчмарков WPF-рендеринга treemap на миллионах узлов; требуется прототип и замер.
- Исследование NN/g о сравнении treemap и sunburst по точности восприятия в сессии не получено.

## 3. Аналитика использования и ИИ: уверенность, факт vs догадка, объяснения, план, коридор Autopilot, журнал, undo

### Takeaway
Следовать 18 HAX-гайдлайнам и PAIR: показывать, что система умеет и насколько хорошо; уверенность — категориями с указанием действия; объяснения — «почему» с источниками фактов; эффективные исправления и отмена; модель предлагает, детерминированные проверки ограничивают.

### Cited Findings
- 18 гайдлайнов Human-AI Interaction (Microsoft, CHI 2019) сгруппированы по фазам: initially, during interaction, when wrong, over time — [Microsoft Research](https://www.microsoft.com/en-us/research/project/guidelines-for-human-ai-interaction/); HAX Toolkit с Design Library, паттернами и Workbook — [HAX Toolkit](https://www.microsoft.com/en-us/haxtoolkit/ai-guidelines/).
- PAIR: дисплеи уверенности помогают оценить доверие, но статистику (проценты) людям трудно понять; разные группы по-разному понимают вероятность — тестировать варианты рано — [PAIR Explainability + Trust](https://pair.withgoogle.com/chapter/explainability-trust/).
- PAIR: категориальная уверенность (High/Medium/Low) — команда выбирает пороги; «Clearly indicate what action a user should take under each category of confidence» — [PAIR](https://pair.withgoogle.com/chapter/explainability-trust/).
- PAIR: пример общей точности системы «categorizes images with 80% confidence on average» как отдельный тип дисплея (уровень системы, а не элемента) — [PAIR](https://pair.withgoogle.com/chapter/explainability-trust/).
- NN/g: поддерживать Undo, делать его заметным, позволять легко отменить действие и вернуться на шаг — [NN/g User Control and Freedom](https://www.nngroup.com/articles/user-control-and-freedom/).
- Storage Sense выражает правила как «старше N дней»/«не открывались N дней» — понятный пользователю язык условий — [Microsoft Support](https://support.microsoft.com/en-us/windows/manage-drive-space-with-storage-sense-654f6ada-7bfc-45e5-966b-e24aded96ad5).

### Inferences
- Три уровня происхождения утверждения, единые для всего UI (бейдж + иконка + текст, не только цвет):
  - «Факт» — измерено сканом (размер, дата, путь, наличие записи деинсталляции).
  - «Правило» — сработало детерминированное правило каталога (ID правила, напр. `cache.steam.shader`).
  - «Предположение модели» — вывод локального ИИ; всегда со «Почему я так думаю» и уровнем «Высокая/Средняя/Низкая уверенность», и каждой категории сопоставлено действие: Высокая → «можно добавить в план после просмотра», Средняя → «требуется просмотр», Низкая → «только для информации, в план не попадает».
- Аналитика использования формулируется как наблюдение относительно источника данных: «14 программ не запускались 90+ дней · 63 ГБ» + ссылка «Откуда известно» (Prefetch/UserAssist/время доступа, с оговоркой о точности, если `LastAccess` отключён). Если источник неполный — бейдж «Оценка».
- Блок «Почему я так думаю» (развёртываемый): 2–4 пункта фактов с бейджами, затем вывод модели, затем «Что может пойти не так» (последствия) и «Что проверено» (исключения, приложение закрыто, нет открытых дескрипторов).
- Планировщик по фразе («освободи 30 ГБ, игры не трогай»): помощник показывает разбор запроса в виде чипов-ограничений («Цель: 30 ГБ», «Исключить: Игры», «Диск: любой»), которые можно редактировать, и 1–3 варианта плана с компромиссами («Безопасный: 22 ГБ — не достигает цели», «Сбалансированный: 31 ГБ», «Максимальный: 48 ГБ — включает старые установщики»). Кнопка в чате только «Открыть в плане», не «Выполнить» (соответствует §8 концепции).
- Оценка vs измерение: в плане «Ожидается освободить ≈ 31,2 ГБ (оценка)»; в отчёте «Освобождено 29,8 ГБ (измерено по свободному месту тома: было 84,2 → стало 114,0 ГБ)» + расхождение с объяснением (пропущенные занятые файлы, жёсткие ссылки, сжатие NTFS, карантин на том же томе).
- Коридор Autopilot (UI): карточка «Что разрешено без меня» с явными полями — Категории (только из «Известных»), Диски, Мин. возраст данных, Предел за запуск (ГБ), Условие запуска (свободно < X ГБ / расписание), Способ (Корзина/Карантин/Удаление), «Никогда»: личные папки, игры, сохранения, неизвестное. Сводка человеческим языком сверху: «Автопилот может удалить до 10 ГБ кэшей браузеров и временных файлов старше 14 дней на C:, раз в неделю, только при свободном месте < 50 ГБ». Новые предположения модели в коридор автоматически не попадают (§14 концепции).
- Журнал решений: лента записей «Когда · Кто (Вы / Автопилот / Правило) · Что · Объём · Основание · Обратимо до» с фильтрами и кнопкой «Восстановить» там, где возможно; запись о решении модели хранит текст объяснения на момент решения.
- Обратная связь для обучения поведения (HAX «over time»): «Не предлагать больше» / «Всегда исключать эту папку» прямо из карточки; изменения видны в Настройки → Исключения.

### Gaps
- Полный текст 18 HAX-гайдлайнов по номерам в сессии не извлечён (страница отдала только обзор); при необходимости процитировать конкретные G1–G18 — перепроверить.
- NN/g-статья про explainable AI проиндексирована, но содержимое не использовано; конкретные рекомендации NN/g по объяснениям не процитированы.

## 4. UX разрушительных действий: подтверждения, необратимость, прогресс с пропусками, частичный результат, отчёт

### Takeaway
Подтверждать редко и конкретно: что именно, сколько, куда, обратимо ли. Обратимое (Корзина/Карантин) — без модального диалога, с undo; необратимое — отдельный экран плана с явной формулировкой и кнопкой-глаголом. Прогресс и отчёт должны честно показывать пропуски и частичность.

### Cited Findings
- Подтверждение должно пересказать запрос пользователя и объяснить, что сделает компьютер, со специфичной информацией; «these 2 items» без имён бесполезно — [NN/g Confirmation Dialogs](https://www.nngroup.com/articles/confirmation-dialog/).
- Если предупреждать слишком часто, ответ становится автоматическим и предупреждение игнорируется; решать через task analysis по тяжести и частоте; главное — не злоупотреблять и быть конкретным — [NN/g](https://www.nngroup.com/articles/confirmation-dialog/).
- У Microsoft есть расширенные гайдлайны по confirmation dialogs, включая bulk confirm для последовательности действий — [NN/g ссылается](https://www.nngroup.com/articles/confirmation-dialog/).
- Undo должен быть доступен и обнаруживаем; лёгкая отмена действия — [NN/g](https://www.nngroup.com/articles/user-control-and-freedom/).
- BleachBit обязывает шаг «preview» до «delete» — [BleachBit](https://www.bleachbit.org/features).

### Inferences
- Матрица подтверждений:
  - Карантин/Корзина, ≤ порога → без диалога; InfoBar «Перемещено в карантин 4,8 ГБ · Отменить» (10–15 с) + запись в Журнале.
  - Необратимое (WinSxS cleanup через DISM, Windows.old, точки восстановления, hiberfil, `vssadmin`, перезапись свободного места) → в плане отдельная группа «Без возможности возврата» с иконкой и текстом; финальная кнопка называется действием: «Удалить без возврата 18,4 ГБ», а не «ОК». Без чекбокса «Больше не спрашивать» для этой группы.
  - Высокий объём относительно обычного (по аналогии с NN/g-примером порога) → дополнительное подтверждение.
- Экран выполнения: общий прогресс по объёму и по объектам; текущая категория; живой счётчик «Обработано 12 840 · Пропущено 37 · Ошибок 2»; раскрываемый список пропусков с причиной («Файл занят: Steam.exe — закройте Steam и повторите», «Изменён после анализа», «Нет прав»); кнопка «Остановить после текущего объекта» (не «Отменить всё», т.к. удалённое не возвращается — §7 концепции).
- Отчёт: заголовок-статус «Готово», «Готово частично» или «Не выполнено» (иконка + текст); три числа — «Освобождено на диске», «Перемещено в карантин (место не освобождено)», «Пропущено»; список по категориям; «Что можно вернуть и до какой даты»; действия «Повторить пропущенные», «Открыть журнал», «Экспорт отчёта (скрыть пути)».
- Восстановление: при конфликте имени — выбор «Переименовать / Пропустить / Заменить (явно)», без тихой перезаписи (§12 концепции).

## 5. Современный Windows-вид в WPF .NET 10

### Takeaway
.NET 9+ даёт встроенную Fluent-тему через `ThemeMode` (Light/Dark/System/None), системный accent через `SystemColors.Accent*`; .NET 10 расширил Fluent-стили и исправил падения в HighContrast, но поддержка «still in progress». NavigationView в WPF нет «из коробки» — shell собирается вручную или берётся сторонняя библиотека. Live regions требуют явного `RaiseAutomationEvent`.

### Cited Findings
- `ThemeMode`: значения `Light`, `Dark`, `System` (по настройке Windows), `None` (по умолчанию, Aero2); задаётся на `Application` или на отдельном `Window` — [What's new in WPF .NET 9](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net90).
- Fluent-тема даёт Windows 11-вид со встроенными светлым и тёмным режимами и поддержкой accent color — [WPF .NET 9](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net90).
- Accent: `SystemColors.AccentColor`, `AccentColorLight1..3`, `AccentColorDark1..3` (+ `...Brush`, `...Key`); доступны и без Fluent-темы; использовать через `DynamicResource`, чтобы цвет обновлялся при смене accent на лету — [WPF .NET 9](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net90).
- .NET 10: Fluent-стили добавлены для DatePicker, GridSplitter, GridView, GroupBox, Hyperlink, Label, NavigationWindow, RichTextBox, TextBox; исправлена анимация Expander; исправлены падения с `HighContrast`; добавлен `RecognizesAccessKey`; RTL-фиксы; «Fluent UI style support is still in progress» — [What's new in WPF .NET 10](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net100).
- .NET 10: улучшена производительность (меньше аллокаций в UI Automation и файловых диалогах, рендер шрифтов, dynamic resources, XAML parsing) — [WPF .NET 10](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/whats-new/net100).
- Mica: непрозрачный материал для фона долгоживущих окон, сэмплирует обои один раз (ради производительности), при неактивном окне переходит в нейтральный цвет; применять как базовый слой, приоритет — область заголовка; для Win32 есть отдельная инструкция — [Mica material](https://learn.microsoft.com/en-us/windows/apps/design/style/mica).
- Типографика Windows 11 (epx): Caption 12/16, Body 14/20, Body Strong 14/20 semibold, Body Large 18/24, Subtitle 20/28, Title 28/36, Title Large 40/52, Display 68/92; Bold и Italic не входят в ramp — использовать Semibold — [Typography in Windows](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography).
- NavigationView `PaneDisplayMode=Auto`: развёрнутая панель ≥ 1008 px, `LeftCompact` (иконки) 641–1007 px, `LeftMinimal` (только кнопка меню) ≤ 640 px; при переопределении ресурсов фона давать словари Default и HighContrast — [NavigationView](https://learn.microsoft.com/en-us/windows/apps/design/controls/navigationview).
- Контрастные темы: hard-coded цвета и неверные пары SystemColor ломают контраст; брать цвета из ресурсов темы — [Contrast themes](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/high-contrast-themes).
- WPF live regions: в .NET Framework 4.7.1 добавлены `AutomationProperties.LiveSetting` (attached, XAML), `AutomationPeer.GetLiveSettingCore`, `AutomationElementIdentifiers.LiveRegionChangedEvent`; при изменении данных разработчик сам обязан поднять событие — [.NET Blog (4.7.1 accessibility)](https://devblogs.microsoft.com/dotnet/wp-json/wp/v2/posts/14515). Уровни «вежливости» Off/Polite/Assertive — [UWP AutomationProperties.LiveSetting](https://learn.microsoft.com/en-gb/uwp/api/windows.ui.xaml.automation.automationproperties.livesetting?view=winrt-18362); поле события — [LiveRegionChangedEvent](https://learn.microsoft.com/nl-nl/dotnet/api/system.windows.automation.automationelementidentifiers.liveregionchangedevent).

### Inferences
- `App.xaml`: `ThemeMode="System"`; в Настройках «Тема: Как в Windows / Светлая / Тёмная» → переключение `Application.ThemeMode` в рантайме. Контрастная тема — не отдельный выбор приложения, а следование системной High Contrast (прототип предлагает «Контрастная» как кнопку — лучше показывать её как статус «Включена контрастная тема Windows»).
- Shell: собственный `NavigationView`-подобный контрол (ListBox с иконками Segoe Fluent Icons + Frame/ContentControl) с тремя брейкпойнтами из гайдлайна; либо сторонняя библиотека (WPF-UI и др.) — проверить совместимость с встроенной Fluent-темой .NET 10, чтобы не тянуть две системы стилей. Это не проверено в сессии.
- Mica для WPF: через `DwmSetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` по Win32-инструкции; на Windows 10 — откат на сплошной фон. Mica только для фона окна/заголовка, контент — на непрозрачных «картах».
- Типографика: Segoe UI Variable (Win11), фолбэк Segoe UI (Win10); ключевые числа (свободно ГБ) — Title Large 40/52; заголовки карточек — Subtitle 20/28; тело — Body 14/20; пути — Caption 12/16 с моноширинным вариантом в подробном режиме. Цифры табличные (tabular figures) в колонках размеров.
- Narrator: `LiveSetting=Polite` на строке статуса скана/выполнения, событие поднимать не чаще 1 раза в 2–5 с (иначе спам); `Assertive` — только для ошибки/завершения. `AutomationProperties.Name` у всех иконок-кнопок, `HelpText` у бейджей «Факт/Правило/Предположение».
- DPI: Per-Monitor V2 в манифесте; иконки векторные; все размеры в DIP; тестировать 100/150/200 % и «Увеличение текста» Windows.
- Клавиатура: Ctrl+F — поиск по дереву/настройкам; F5 — повторить скан; Space — отметить; Del — добавить в план (не удалять!); Alt+←/Backspace — вверх по дереву; F6 — переход между регионами (навигация/контент/панель помощника).

### Gaps
- Точный API Mica/backdrop для WPF-окон в .NET 10 (есть ли встроенное свойство, напр. `WindowBackdropType`) не подтверждён первоисточником в этой сессии — проверить по docs .NET 10/11.
- Состояние встроенных Fluent-стилей для `TreeView`/`DataGrid` на .NET 10 не проверено (список .NET 10 их не упоминает).

## 6. Онбординг, пустые состояния, ошибки, загрузка модели

### Takeaway
Первый запуск короткий и без очистки: выбрать диски → режим «Только анализ» по умолчанию → объяснить локальность → предложить (не навязать) модель с размером и требованиями. Каждый процесс имеет состояния ожидания, выполнения, пусто, частично, ошибка (концепция §9).

### Cited Findings
- HAX «initially»: в начале взаимодействия ясно показать, что система умеет и насколько хорошо — [Microsoft Research HAX](https://www.microsoft.com/en-us/research/project/guidelines-for-human-ai-interaction/).
- PAIR: тестировать формы показа уверенности рано, пользователи по-разному понимают вероятность — [PAIR](https://pair.withgoogle.com/chapter/explainability-trust/).
- Storage Sense по умолчанию не трогает Downloads и облако — консервативные дефолты — [Microsoft Support](https://support.microsoft.com/en-us/windows/manage-drive-space-with-storage-sense-654f6ada-7bfc-45e5-966b-e24aded96ad5).
- Концепция: знакомство включает выбор дисков, режим «только анализ», объяснение локальной обработки, предложение подключить интеллект; скачивание модели показывает объём и назначение; приложение не начинает очистку автоматически — [PROJECT_PROMPT_RU.md §7](file:///D:/Projects/codex/cleaner/PROJECT_PROMPT_RU.md).

### Inferences
- Онбординг (3 шага, пропускаемых): 1) «Что проверить?» — плитки дисков C:, D: с занятостью, чекбоксы; 2) «Как работать?» — радиокнопки трёх режимов, по умолчанию «Только анализ»; 3) «Помощник» — карточка: «Локальная модель · 2,3 ГБ · работает без интернета · нужна видеокарта с 6 ГБ памяти или 16 ГБ ОЗУ · Ваш ПК: подходит (уровень Средний)», кнопки «Скачать сейчас» / «Позже». Без модели — полный базовый функционал.
- Детекция уровня железа (tiers): Нет (менее X ГБ ОЗУ) / Базовый (CPU) / Средний (iGPU/NPU) / Высокий (dGPU); показывать вывод и «почему» (ОЗУ, VRAM, NPU), предлагать модель по уровню; выбор можно поменять.
- Загрузка модели: размер, оставшееся время, пауза/продолжение, проверка хэша, куда сохраняется и сколько места займёт на каком диске (ирония: чистильщик занимает место — сказать честно). Ошибка сети → «Загрузка прервана. Скачано 1,1 из 2,3 ГБ. Продолжить».
- Пустые состояния: «Ещё нет данных — запустите первый анализ» (Обзор); «Подходящих известных категорий не найдено. Это нормально: на диске мало временных данных» (Рекомендации); «История появится после второго анализа» (график роста); «Автопилот выключен. Ничего не выполняется без вас».
- Ошибки: нет прав → «Часть папок пропущена: нет доступа (37). Запустить проверку с правами администратора?» (UAC в контексте, а не при старте — §7 концепции); диск отключён; модель не загрузилась → помощник недоступен, базовые функции работают.

### Gaps
- Конкретные требования к железу для локальной модели — в зоне других исследователей; цифры выше — плейсхолдеры, не факты.

## 7. Уведомления (toast) из разовой задачи планировщика без фонового процесса
